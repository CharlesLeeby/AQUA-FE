# A02 恶化原因：出生观测损失进入初始化三维重建

更新时间：2026-09-08T02:35:14+08:00。既有输入的事后机制诊断，归属 EXP-20260906-012 后续审计。
不修改原结果；不解除 `NO_EXPANSION`；新前端运行和新 VIO 回放均为 0。

## 结论

**已确认的直接致害操作是启动期注册 donor 观测的联合删除，不需要加入错误 learned 点就能复现 A02 恶化。**
本轮进一步定位：这些删除改变了首次初始化三维重建的多帧观测输入，而不是首先改变滑窗选择或两帧相对位姿。
“不删除成熟 KLT、只动 age-1 新生点”保护了一个前端规则，**没有保护初始化所需的全部观测约束**。

不能把更细的解释都升级为因果事实：具体哪次尺度/重力检验跨过边界、三个观测各自的作用、
失败后偏置保留对误差的独立贡献，仍是 **Unknown**。本轮未实施修复或新算法策略。

## 直接致害证据来自已有严格对照

[原 A02 donor-delete-only 对照](../frontend_coverage_monotone_router_v2_donor_delete_diagnostic/report.md)
只删除注册的八个观测，不加入候选；保留其余观测、IMU、时间戳和同一后端。
三重复在同一 42 poses / 41 s / 41 个 1 s RPE 对上均有效，evo 已交叉验证。
以下是原表中位数，不是本轮重算，不与其他 common support 拼接。

| 输入 | fixed-scale APE / RPE（m） | Sim(3) APE（m） | 事后拟合 scale |
|---|---:|---:|---:|
| KLT | 0.141317 / 0.022697 | 0.060774 | 0.898634 |
| 仅删八个观测 | 1.073158 / 0.102008 | 0.045444 | 0.513513 |

固定尺度显著恶化、拟合尺度后形状误差并未同方向恶化，说明恶化主要表现为**与 proxy 的尺度不一致**。
这不是准许静默尺度拟合，也不是独立 GT 绝对误差。事后 scale 不是初始化器内部求出的 scale。
`DELETE_SUFFICIENT` 的范围仍是这八个观测的联合操作，不是某一个 donor 单独致因。

## 本轮怎样继续定位

只编译了一个独立、可丢弃的诊断驱动，**链接原冻结 libvins_lib.so**，没有重编译 VINS。
用现有 KLT 和 delete-only bag 调用原 `FeatureManager` 与 `MotionEstimator::solveRelativeRT`，
严格复用单目回调解码、原 YAML 的视差/时间偏移值以及初始化调用间隔。
诊断在第一次成功的两帧相对位姿处停止：不调用 SFM、BA、IMU 对齐或完整 Estimator。
此后 SFM 失败可能改变滑窗，不能在缺少记录时继续假装重现历史内部状态。

检查结果（零基 feature 输出帧，不是原图索引）：

- 两臂均在输出帧 17 首次求得相对位姿；此前均有五次 relativePose 失败，与已有 INFO 日志的拒绝次数一致。
- 0–17 的全部滑窗选择一致。进入首次 SFM 前的窗口均为 `[1,2,3,4,5,6,7,8,13,16,17]`。
- 选中的两帧是输出帧 1 与 17；**323 对对应点的 ID、坐标、顺序完全相同**。
- 调用冻结相对位姿函数得到的旋转、平移差均为 0。
- 输入原始 feature 列表顺序有变化，但**371 条多帧轨迹的顺序完全一致**。
  因此不能把本例归因于“首次 RANSAC 对应点顺序被打乱”。

随后送往 SFM 构建的多帧观测数是 **3834 → 3831**，多帧轨迹仍为 371 条。
三个具体差异为：

| donor ID | 被省略的输出帧 | 首次 SFM 前 KLT 窗内观测数 | delete-only 观测数 | 首帧后是否仍出现 |
|---:|---:|---:|---:|---|
| 363 | 2 | 10 | 9 | 是，同 ID |
| 372 | 3 | 9 | 8 | 是，同 ID |
| 377 | 4 | 8 | 7 | 是，同 ID |

另外五个被删 ID（362、365、371、373、376）在这个前缀内都只有一个观测；
冻结 SFM 代码不为单观测点完成三角化。**出生时 age=1 的点，稍后可以成为多帧初始化点，
其出生观测仍留在初始窗口里；只删一帧并不等于删掉一个无用观测。**
这些后续观测只用于本次事后解释，从未作为在线准入规则的未来信息。

本轮实测的是“冻结特征管理/相对位姿函数的输入输出”，不是历史逐 ID 残差日志。
未运行仅删三个观测的 VIO 对照，不把八观测的充分性结论擅自缩小到三个或一个。
首个 SFM 之后的完整内部状态仍未重现。

## 为什么小的前端变化可能延续到后端

只读代码显示了一个有记忆的初始化过程：

1. `initial_sfm.cpp:87–125,174–225,271–285` 按各轨迹可见帧进行三角化和初始 BA。
   363/372/377 的出生观测损失改变其多视图输入；这不是单纯减少总 feature 数。
2. `initial_aligment.cpp:16–47` 在检查线性尺度/重力结果之前，先计算陀螺偏置增量，
   用 `Bgs[i] += delta_bg` 更新偏置并重新传播 IMU 预积分。
3. 同文件末尾只在 `VINS_INITIAL_ROLLBACK_ON_FAILURE` 为非零时回滚失败尝试的偏置。
   已有 30 份环境记录为空，对此判断等价于未开启；原尝试失败并不是“完全没有改变状态”。
4. 已有日志确实呈现不同的校准/拒绝序列：KLT 八次校准、七次对齐拒绝；
   原删点/学习/matched 与续传各四次校准、三次拒绝，之后接受初始化。

原日志所打印校准增量之和（三重复逐分量中位数，rad/s）为：

| 输入 | 累计打印增量 x / y / z |
|---|---|
| KLT | -0.0317063 / 0.0149348 / -0.0449110 |
| 原 delete-only | -0.0265696 / 0.0134640 / -0.0452921 |
| 续传 XFeat | -0.0265700 / 0.0134631 / -0.0452872 |

这是**有打印精度限制的增量累加**，不是真实传感器偏置、最终优化后偏置或单独致因证据。
它与代码一起表明初始化尝试有历史依赖，但不能证明开启回滚就会修好；本轮没有修改该开关。

**Hypothesis / Inference：** 出生观测损失改变初始视觉结构，在低激励条件下经视觉—IMU对齐和
保留的尝试历史进入不同的尺度结果；单纯延长学习链无法保证恢复被改变的初始化。
完整路径中未记录的三维结构、重力和尺度数值仍不能由最终轨迹倒推为事实。

## 原因、修复边界与唯一下一步

- **Confirmed fact：** 原八观测联合删除足以致害；首次相对位姿之前的帧选择/对应点/位姿相同，
  首次 SFM 多帧输入少了三条轨迹的出生观测；失败尝试中的偏置更新在当前代码/记录选项下不自动回滚。
- **设计层问题：** 把“保护成熟点、保持数量/覆盖”解释成后端 no-harm，是超过证据的保证。
  初始化约束集合已经被改变，哪怕每条 donor 后面都能继续回来。
- **Unknown：** 精确的尺度/重力拒绝子条件、单 donor 或三观测子集的充分性、回滚的独立效果、
  本版新删除集合的独立删除归因。
- **修复：Not evaluated。** 没有改变任何方法、门、后端代码/参数或原结果；六窗仍是 2 WIN / 8 TIE / 2 LOSS，
  新窗口验证 0。不因找到局部机制自动重开第二个算法变体。

**唯一有针对性的下一项诊断建议（尚未授权/未执行）：** 对原 A02 KLT 与原 delete-only 输入开展
单独的“只增加初始化数值日志”对照，记录每次重力模长、线性/细化尺度和接受/拒绝，
不改变算法或门，不计入冻结 benchmark，不用它挑更好轨迹。需要独立协议与明确授权；
现有 `NO_EXPANSION` 仍有效，不在本轮自动执行。
